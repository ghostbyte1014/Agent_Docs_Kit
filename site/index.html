The problem → the outcome

Turn scattered project knowledge into records a team can inspect.

Missing setup notes, stale decisions, and inconsistent reviews create uncertainty. The kit gives those concerns a stable home, a focused check, and an explicit evidence trail.

01

Scattered knowledge

Build a predictable documentation tree for system facts, decisions, test evidence, operations, proposals, and archives.

02

Silent documentation drift

Check required files, placeholders, headings, metadata, and local links. A structural pass never claims the prose is factually correct.

03

Inconsistent quality reviews

Use stable control and practice IDs to record evidence, ownership, remediation, verification, and limitations.

How it works

Inspect → choose scope → collect evidence → keep a record.

The CLI creates files and runs documentation structure checks. A human or authorized AI-assisted workflow investigates security and engineering questions.

  1. 01

    Inspect context

    Read repository instructions and locate the code, configuration, tests, and records that can answer the question.

  2. 02

    Choose one scope

    Select a documentation area, security phase, or engineering topic. Define exclusions before the review grows.

  3. 03

    Collect evidence

    Use repository paths, command output, metrics, or observations from an explicitly authorized environment. Separate facts from inference.

  4. 04

    Keep a durable record

    Record status, impact, remediation, owner, verification, and limitations in the project. A generated worksheet begins Unverified.

Three jobs, clear boundaries

Choose the workflow that matches the work.

The catalog contains seven documentation areas, 12 security phases, and 14 engineering topics. These are selectable guidance areas, not 33 automatic scans.

01 / Documentation

Maintain project memory with every material change.

Setup supplies an agent policy and manual impact loop; checks cover required files, placeholders, headings, metadata, and local links.

Read purpose and boundaries →

What it does

Creates a navigable project record, guides compatible agents to update affected records, and reports structural issues with actionable paths.

What it does not do

The instruction file does not run an agent, and a structural pass does not prove statements are true or current.

Example output

PASS required-document docs/README.md

Persist text, Markdown, or JSON reports only when --report is explicit.

02 / Security

After documentation setup, create a scoped worksheet and record evidence.

Capture risk, remediation, owner, and verification for each applicable control.

Review the security model →

What it does

Supplies stable controls and an evidence-first status model for a bounded review.

What it does not do

Worksheet creation is not a vulnerability scan, security certification, or authorization to test a target.

Example output

PassFailUnverifiedN/A

A policy can require a blocking decision; enforcement needs an explicit CI or release control.

03 / Engineering

After documentation setup, review design and operations against evidence.

Topics cover testing, performance, reliability, APIs, maintenance, deployment, observability, and cost.

Reproducible team use

Pin a reviewed version

Replace @latest with an approved version such as @ghostbyte/agent-docs-kit@6.0.0. The website examples use @latest for discovery, not reproducible automation.

AI-first documentation

Repository instructions, not a built-in model.

The workflow is designed primarily for compatible AI coding agents, while remaining usable manually. Setup creates AGENTS.md only when absent; the package does not bundle an AI model or background process.

Agent required for agent-assisted updates

Connect policy, skill, and an active coding agent.

npx @ghostbyte/agent-docs-kit@latest skill install --target project

Open or restart a compatible agent so it reads AGENTS.md and discovers .agents/skills/. Give it repository write access appropriate to the task. Provider support varies; the same impact loop remains available manually.

New versus existing projects: Choose start new or start existing; the CLI does not guess project maturity or whether an agent is running. Setup creates AGENTS.md when absent, preserves an existing one exactly, and leaves unrelated repository skills untouched.

Suggested promptUse $manage-project-quality. Inspect this repository, determine the current Agent Docs stage, and guide me through the next safe step. Do not infer facts without evidence.
Read-only commit or push remindernpx @ghostbyte/agent-docs-kit@latest suggest reviews --staged npx @ghostbyte/agent-docs-kit@latest suggest reviews --base origin/main

Git integration: The suggestion command prints documentation confirmation and path-based review candidates but creates no worksheet. Teams may call it from an explicitly managed hook or CI job. The package never silently installs hooks, changes Git configuration, or blocks a commit or push.

Private repositories: Sending code to an AI provider can transfer it under that provider's terms and organization settings. Installing this package is not approval to share private code, credentials, personal data, or vulnerability evidence.

Trust and limitations

Useful automation without hidden authority.

◇

Inert installation

No install lifecycle hook changes a repository. Setup, reports, templates, and skill installation require explicit commands.

◎

Local project files

The CLI has no project telemetry service. npm/npx and optional AI providers have their own data flows and policies.

⌁

Bounded security work

Worksheet creation runs no active scan. Testing a service or environment requires explicit authorization for the exact target.

↺

Evidence-first status

Fresh findings start Unverified. Pass, Applied, and other conclusions require evidence, ownership, and a verification step.

CLI reference

Know what writes before you run it.
