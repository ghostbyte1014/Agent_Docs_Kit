When another user gives the kit to an AI

The package is context, not automatic authority.

The AI should inspect the repository, determine the current stage, explain proposed writes, keep unknowns explicit, and ask for authorization before active security testing. Installing the package or skill alone does not initialize files or perform an audit.

How agentic coding fits

The kit supplies project memory and review rules. Your coding agent performs the work you request.

Agent Docs & Quality Kit does not bundle an AI model or start a background service. It prepares a durable workspace that humans and compatible coding agents can read, update, and verify together.

  1. 1
    Initialize the workspace

    setup creates the configuration and documentation structure. Existing files are protected by default.

  2. 2
    Install the project skill

    skill install --target project adds the focused instructions and references under .agents/skills/.

  3. 3
    Start the coding agent

    Open or restart a supported agent in the repository, invoke $manage-project-quality, and give it a specific documentation, security, or engineering goal.

  4. 4
    Keep the result with the project

    The agent cites repository evidence and writes review records into docs/, where the team can inspect and maintain them.

Suggested first promptUse $manage-project-quality. Inspect this repository, determine the current Agent Docs stage, and guide me through the next safe step. Do not infer facts without evidence.

Using another AI tool? If it supports repository skills, point it to .agents/skills/manage-project-quality/SKILL.md. If it does not, the generated docs/README.md, focused CLI guides, and worksheets still provide a complete manual workflow.

Three jobs, clear boundaries

Choose the quality lens that matches the work.

Documentation, security, and engineering overlap, but they do not mean the same thing. The kit keeps their evidence and consequences separate.

01 / Documentation governance

Make the repository explain itself.

Use seven canonical guidance areas to preserve project scope, architecture, decisions, operational knowledge, test evidence, proposals, and history in a structure people and agents can navigate.

Read the purpose and boundaries →

Use it when

  • Starting or inheriting a project
  • Important decisions live only in chat
  • Documentation conflicts with the code
  • Operations depend on tribal knowledge

What it checks

  • Missing or duplicate sources of truth
  • Scope and architecture drift
  • Broken navigation and stale records
  • Undocumented setup and recovery paths

Document states

CurrentNeeds updateReferenceArchived

Documentation describes governance. Hooks and CI are what make a policy technically enforceable.

02 / Security assurance

Turn controls into verifiable evidence.

Review security across 12 lifecycle phases, from design and local development through release, monitoring, and ongoing operations. Missing evidence is never treated as a pass.

Review the security model →

Use it when

  • Designing a sensitive feature
  • Preparing an API or cloud deployment
  • Running a pre-release security gate
  • Reviewing post-release readiness

Safety boundary

  • Passive repository review can start locally
  • Active testing needs explicit authorization
  • Staging is preferred over production
  • Secrets are redacted from reports

Security verdicts

PassFailUnverifiedN/A

Critical and High failures block release by default unless an accountable owner records a time-bounded exception.

03 / Engineering review

Improve the system without importing needless complexity.

Assess maintainability, reliability, performance, testing, data modeling, operations, and cost using recommendations grounded in the project’s real scale and constraints.

Explore the toolkit architecture →

Use it when

  • Reviewing a design or pull request
  • Investigating slow or fragile behavior
  • Planning testing and observability
  • Evaluating infrastructure cost

Fourteen topic areas

  • Reliability, observability, and deployment safety

From request to useful record

A review process you can inspect.

Every workflow follows the same evidence discipline while producing an outcome appropriate to its purpose.

  1. 01

    Inspect context

    Read repository instructions, identify the technology and locate the files that can actually answer the question.

  2. 02

    Select scope

    Choose one workflow, then a specific documentation area, security phase, or engineering topic. Define exclusions before the review grows.

  3. 03

    Collect evidence

    Use code paths, configuration, tests, command output, or authorized external settings. Separate facts from inference.

  4. 04

    Record the result

    Write status, impact, remediation, owner, verification step, and limitations into a durable project report.

Installation guide

From a clean terminal to your first safe run.

Start with Node.js 22 or newer, then choose between running on demand with npx or installing the shorter global command.

Step 01

Check Node.js and npm

The CLI requires Node.js 22 or newer. npm is included with standard Node.js installations.

node --version npm --version
Path A · Recommended

Run without installing

Use the published package directly. Nothing is added to the project or installed globally.

  1. Confirm the CLI is availableThis fetches the current published version and prints its help.
    npx @ghostbyte/agent-docs-kit@latest --help
  2. Preview the documentation setupThe dry run reports intended writes without changing files.
    npx @ghostbyte/agent-docs-kit@latest setup --dry-run
  3. Choose your starting pathGet complete instructions for a new project, existing project, AI-assisted workflow, or manual workflow.
    npx @ghostbyte/agent-docs-kit@latest start
Path B · Repeated use

Install the global command

Install once on your workstation, then use the shorter agent-docs command in any project.

  1. Install the latest versionInstallation is inert and does not configure the current project.
    npm install --global @ghostbyte/agent-docs-kit@latest
  2. Verify the installationThe installed version should print without an error.
    agent-docs --version agent-docs --help
  3. Run a safe previewAfter installation, every command can begin with agent-docs.
    agent-docs setup --dry-run
Step 03

Check for a newer global version

Compare the installed and published versions. Updating is always explicit; the CLI never updates itself.

agent-docs --version npm view @ghostbyte/agent-docs-kit version
npm install --global @ghostbyte/agent-docs-kit@latest
Team projects Install as a project dependency

Record the package version in the project lockfile. Run its executable through npx so npm resolves the local binary.

npm install --save-dev @ghostbyte/agent-docs-kit npx agent-docs --help
Troubleshooting

If agent-docs is not recognized

Close and reopen the terminal after a global installation, then run npm config get prefix and confirm npm’s global executable directory is on your PATH. In Windows PowerShell, use npm.cmd or npx.cmd if script execution blocks the corresponding PowerShell shim.

What the installed skill does

The skill classifies the request, establishes scope and safety boundaries, loads only the required references, inspects repository evidence, applies the correct status model, and produces a durable result.

  2. 2Select standard or learning interaction style
  3. 3Load shared evidence rules plus one relevant reference

Complete CLI reference

Know what every command does before you run it.

Commands marked “writes” create an owned scaffold or record. Scaffolds skip existing files; reports and templates select a collision-safe numbered filename. Read-only commands inspect or print information without changing the target project.

Interactivenpx @ghostbyte/agent-docs-kit@latest

Open the guided menu

Choose documentation setup, documentation audit, security audit, engineering review, project-skill installation, or package validation. In a non-interactive shell, it prints help instead of waiting for input.

Read-onlynpx @ghostbyte/agent-docs-kit@latest start [new|existing|agent|manual]

Show a complete onboarding path

Explains the ordered steps, safety boundary, and exact commands for a new project, an existing project, AI-assisted work, or manual work. With no path argument, it shows all four choices.

Read-onlynpx @ghostbyte/agent-docs-kit@latest next

Continue from project state

Inspects the configured workspace, starter prompts, saved audits, and open worksheets, then prints the current stage and one concrete set of next actions. It does not write files.

Writesnpx @ghostbyte/agent-docs-kit@latest setup

Create the documentation workspace

Adds `.agent-docs/config.json` and the initial `docs/` hierarchy for system, project, development, testing, operations, future work, and archives. Use `--dry-run` first; existing files are skipped.

Read-only*npx @ghostbyte/agent-docs-kit@latest audit documentation

Check documentation health

Checks configured required documents, duplicate headings, placeholders, relative links, anchors, and optional metadata. Add --strict for CI, --format for text, Markdown, or JSON, and --report to persist the result.

Read-onlynpx @ghostbyte/agent-docs-kit@latest list documentation

List documentation areas

Prints the seven canonical documentation area IDs, slugs, and names from the same catalog used by security and engineering.

Read-onlynpx @ghostbyte/agent-docs-kit@latest documentation guide <area>

Read focused documentation guidance

Prints one canonical area with stable DOC-* controls and evidence questions without loading the entire documentation library.

Read-onlynpx @ghostbyte/agent-docs-kit@latest list security

List security audit phases

Prints the 12 available phase IDs, slugs, and names so you can select a precise review scope without loading every security reference.

Writesnpx @ghostbyte/agent-docs-kit@latest security worksheet <phase>

Create a scoped security worksheet

Creates a dated, configuration-aware report with control IDs, priority, evidence, remediation, owner, and verification. It does not run active scans or claim controls pass. The v4 audit security form remains an alias.

Read-onlynpx @ghostbyte/agent-docs-kit@latest list engineering

List engineering topics

Prints all 14 review topics and selectors, including reliability, observability, deployment safety, API compatibility, and capacity.

Writesnpx @ghostbyte/agent-docs-kit@latest engineering worksheet <topic>

Create an engineering review worksheet

Creates a dated report with practice ID, evidence, impact, recommendation, owner, and verification. Recommendations remain advisory unless evidence establishes a separate defect. The v4 review engineering form remains an alias.

Read-onlynpx @ghostbyte/agent-docs-kit@latest template list

List documentation templates

Shows the available ADR, runbook, change record, incident review, and test evidence templates.

Writesnpx @ghostbyte/agent-docs-kit@latest template create <type> --name <slug>

Create a durable project record

Creates a dated template below the configured documentation root. Use --name for a descriptive filename; repeated unnamed records receive a safe numeric suffix.

Writesnpx @ghostbyte/agent-docs-kit@latest skill install --target project

Shared options

Control scope and output.

--cwd <path>
Run against another project directory instead of the current directory.
--dry-run
Preview owned file writes without creating or replacing anything.
--force
Replace files owned by the selected command. Unrelated files remain outside its scope.
--style standard|learning
Choose concise findings or add “why this matters” teaching context.
--report
Persist a documentation-audit result instead of printing it only.
--strict
Return a failing exit code when a documentation audit finds a problem.
--format text|markdown|json
Choose terminal or persisted documentation-audit output.
--name <slug>
Give a template record a lowercase, hyphenated filename suffix.
--phase / --topic
Alternative named selectors for security phases and engineering topics.
