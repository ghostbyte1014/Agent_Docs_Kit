Three jobs, clear boundaries

Choose the quality lens that matches the work.

Documentation, security, and engineering overlap, but they do not mean the same thing. The kit keeps their evidence and consequences separate.

01 / Documentation governance

Make the repository explain itself.

Preserve project scope, architecture, decisions, operational knowledge, test evidence, and change history in a predictable structure that both people and agents can navigate.

Read the purpose and boundaries →

Use it when

  • Starting or inheriting a project
  • Important decisions live only in chat
  • Documentation conflicts with the code
  • Operations depend on tribal knowledge

What it checks

  • Missing or duplicate sources of truth
  • Scope and architecture drift
  • Broken navigation and stale records
  • Undocumented setup and recovery paths

Document states

CurrentNeeds updateReferenceArchived

Documentation describes governance. Hooks and CI are what make a policy technically enforceable.

02 / Security assurance

Turn controls into verifiable evidence.

Review security across 12 lifecycle phases, from design and local development through release, monitoring, and ongoing operations. Missing evidence is never treated as a pass.

Review the security model →

Use it when

  • Designing a sensitive feature
  • Preparing an API or cloud deployment
  • Running a pre-release security gate
  • Reviewing post-release readiness

Safety boundary

  • Passive repository review can start locally
  • Active testing needs explicit authorization
  • Staging is preferred over production
  • Secrets are redacted from reports

Security verdicts

PassFailUnverifiedN/A

Critical and High failures block release by default unless an accountable owner records a time-bounded exception.

03 / Engineering review

Improve the system without importing needless complexity.

Assess maintainability, reliability, performance, testing, data modeling, operations, and cost using recommendations grounded in the project’s real scale and constraints.

Explore the toolkit architecture →

Use it when

  • Reviewing a design or pull request
  • Investigating slow or fragile behavior
  • Planning testing and observability
  • Evaluating infrastructure cost

Nine topic areas

  • Queries, networking, and rate limits
  • Production debugging and code review
  • Data modeling and testing strategy
  • Cloud cost and message queues

Engineering outcomes

AppliedPartialRecommendedUnverifiedN/A

Recommendations are normally advisory. Security vulnerabilities and correctness defects are reported separately.

From request to useful record

A review process you can inspect.

Every workflow follows the same evidence discipline while producing an outcome appropriate to its purpose.

  1. 01

    Inspect context

    Read repository instructions, identify the technology and locate the files that can actually answer the question.

  2. 02

    Select scope

    Choose one workflow, then a specific security phase or engineering topic. Define exclusions before the review grows.

  3. 03

    Collect evidence

    Use code paths, configuration, tests, command output, or authorized external settings. Separate facts from inference.

  4. 04

    Record the result

    Write status, impact, remediation, owner, verification step, and limitations into a durable project report.

Complete CLI reference

Know what every command does before you run it.

Commands marked “writes” create an owned scaffold or report. They skip existing files by default. Read-only commands inspect or print information without changing the target project.

Interactivenpx @ghostbyte/agent-docs-kit@latest

Open the guided menu

Choose documentation setup, documentation audit, security audit, engineering review, project-skill installation, or package validation. In a non-interactive shell, it prints help instead of waiting for input.

Writesnpx @ghostbyte/agent-docs-kit@latest setup

Create the documentation workspace

Adds `.agent-docs/config.json` and the initial `docs/` hierarchy for system, project, development, testing, operations, future work, and archives. Use `--dry-run` first; existing files are skipped.

Read-only*npx @ghostbyte/agent-docs-kit@latest audit documentation

Check documentation health

Checks whether core configuration and authoritative documents exist. Add `--report` to write a dated JSON result under `docs/03-development/audits/`; without it, results stay in the terminal.

Read-onlynpx @ghostbyte/agent-docs-kit@latest list security

List security audit phases

Prints the 12 available phase IDs, slugs, and names so you can select a precise review scope without loading every security reference.

Writesnpx @ghostbyte/agent-docs-kit@latest audit security <phase>

Create a scoped security worksheet

Creates a dated report under `docs/04-testing/security-audits/`, includes only the selected checklist, and initializes findings as Unverified. It does not run active scans or claim controls pass.

Read-onlynpx @ghostbyte/agent-docs-kit@latest list engineering

List engineering topics

Prints all 9 review topics and their selectors, including query performance, testing strategy, data modeling, production debugging, and cloud cost.

Writesnpx @ghostbyte/agent-docs-kit@latest review engineering <topic>

Create an engineering review worksheet

Creates a dated, topic-specific report under `docs/03-development/engineering-reviews/`. Recommendations remain advisory unless the evidence reveals a separate security or correctness defect.

Writesnpx @ghostbyte/agent-docs-kit@latest skill install --target project

Install the skill for one repository

Copies the complete `manage-project-quality` skill into `.agents/skills/` in the selected project. This is the recommended target when the workflow should travel with the repository.

Writesnpx @ghostbyte/agent-docs-kit@latest skill install --target codex

Install the skill for the current user

Copies the skill into the user’s Codex skills directory. This is an explicit global installation and affects future projects that can discover user-level skills.

Read-onlynpx @ghostbyte/agent-docs-kit@latest validate

Validate the distributed library

Confirms that catalog entries resolve to content, all 12 security and 9 engineering references are present, and the unified skill metadata is intact.

Read-onlynpx @ghostbyte/agent-docs-kit@latest doctor

Check local prerequisites

Reports whether the supported Node.js version and Git are available. It does not install or update either tool.

Open the documentation website

Opens https://ghostbyte1014.github.io/Agent_Docs_Kit/ in the default browser and prints the URL as a fallback for terminals that cannot launch a browser.

Shared options

Control scope and output.

--cwd <path>
Run against another project directory instead of the current directory.
--dry-run
Preview owned file writes without creating or replacing anything.
--force
Replace files owned by the selected command. Unrelated files remain outside its scope.

Persist a documentation-audit result instead of printing it only.

Alternative named selectors for security phases and engineering topics.

What the installed skill does

$manage-project-quality

The skill classifies the request, establishes scope and safety boundaries, loads only the required references, inspects repository evidence, applies the correct status model, and produces a durable result.

  2. 2Select standard or learning interaction style
  3. 3Load shared evidence rules plus one relevant reference
  4. 4Inspect files without guessing unavailable facts
  5. 5Write findings, remediation, verification, and limitations

Installation and first run

Choose how you want to use the kit.

Trying with npx is the fastest path. A project dependency is more reproducible for a team. Global installation is convenient for repeated personal use. Contributors can run directly from the repository.

Recommended first run

Run with npx

Downloads and executes the published version without adding it to the project’s dependencies.

npx @ghostbyte/agent-docs-kit@latest
Team projects

Install locally

Add the CLI as a development dependency so the package version is recorded in your lockfile.

npm install --save-dev @ghostbyte/agent-docs-kit
npx agent-docs
Personal workstation

Install globally

Expose `agent-docs` as a machine-level command. The package still performs no setup until you run a command.

npm install --global @ghostbyte/agent-docs-kit
agent-docs --help
Contributors

Run from source

Clone the repository, verify it, and invoke the local executable while developing the library or site.

git clone https://github.com/ghostbyte1014/Agent_Docs_Kit.git cd Agent_Docs_Kit npm install npm test node bin/agent-docs.mjs
What happens immediately after installation?

Nothing. The package has no install-time lifecycle script. Run `npx agent-docs setup`, an audit/review command, or `npx agent-docs skill install` only when you are ready for that explicit action.
