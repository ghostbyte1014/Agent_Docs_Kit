Documentation

Build or repair the baseline

Use $manage-project-quality. Inspect this repository and complete the documentation baseline from code, configuration, tests, and existing records. Keep unknowns explicit. Run the strict documentation audit when finished.
Security

Choose and review one phase

Use $manage-project-quality. Help me start a passive security review. First show the available security phases with a one-line purpose and ask me to choose one. Then ask for the exact scope, target, and exclusions. Repeat my choices and wait for confirmation before creating or opening the worksheet. After confirmation, inspect repository evidence only. Do not run active tests or use credentials without my explicit authorization for the exact target.
Engineering

Choose and review one topic

Use $manage-project-quality. Help me start an engineering review. First show the available engineering topics with a one-line purpose and ask me to choose one. Then ask for the exact system or change, goal, constraints, and exclusions. Repeat my choices and wait for confirmation before creating or opening the worksheet. After confirmation, inspect representative code, tests, configuration, measurements, and authorized operational evidence.

After you paste the guided prompt

The agent asks before it reviews.

The Security and Engineering prompts above can be pasted as-is. No placeholder editing is required.

  1. 01
    Paste

    Open the project in your agent and paste the prompt.

  2. 02
    Choose

    The agent lists security phases or engineering topics. Select one.

  3. 03
    Define scope

    Name the system, feature, change, or release, plus exclusions.

  4. 04
    Confirm

    The agent repeats the selector and scope, waits for approval, then starts the worksheet and evidence review.

Security prompt typesPhase audit, change review, or release gate

Audit one phase

Use any selector from list security.

Use $manage-project-quality. Perform a passive security audit of [phase] for [scope]. Create or open the matching worksheet, inspect source, configuration, tests, and authorized operational evidence, and complete every applicable control. Keep missing evidence Unverified. Do not run active tests or use credentials without my explicit authorization for the exact target.

Review a change

Focus the audit on one feature or pull request.

Use $manage-project-quality. Review [change] under security phase [phase] for [scope]. Trace the changed code, trust boundaries, authentication, data exposure, dependencies, and tests. Record only evidence-backed findings in the dated worksheet, keep unknowns Unverified, and do not perform active testing without explicit authorization.

Check a release gate

Summarize blockers without claiming automatic enforcement.

Use $manage-project-quality. Assess security phase [phase] for release [release] within [scope]. Inspect the recorded evidence, identify Critical or High failures and unresolved items, verify owners and remediation, and recommend a release decision. State clearly that blocking requires the project's release policy. Do not run active tests without explicit authorization.
Engineering prompt typesTopic review, diagnosis, or design decision

Review one topic

Use any selector from list engineering.

Use $manage-project-quality. Review engineering topic [topic] for [system or change]. Create or open the matching worksheet and inspect representative code, tests, configuration, measurements, and authorized operational evidence. Use only Applied, Partial, Recommended, Unverified, or justified N/A, and separate observed facts from recommendations.

Diagnose a problem

Connect one symptom to a relevant engineering topic.

Use $manage-project-quality. Diagnose [symptom] through engineering topic [topic] for [scope]. Inspect relevant code, configuration, telemetry, tests, and recent changes. Separate confirmed evidence from hypotheses, identify evidence still needed, and record prioritized recommendations, owners, and verification steps in the dated review.

Compare a design decision

Evaluate alternatives against actual constraints.

Use $manage-project-quality. Evaluate [option A] versus [option B] using engineering topic [topic] for [system]. Record the constraints, evidence, tradeoffs, failure modes, and operational impact. Recommend an option only when evidence supports it; otherwise keep the decision Unverified and list the measurements or tests required.

Step-by-step tutorials

Expand only the workflow you need.

A worksheet is a review record, not a completed audit. Your agent must inspect evidence and fill it in.

DocumentationSet up the project record
  1. Preview. Run npx @ghostbyte/agent-docs-kit@latest setup --dry-run --ai from the project root.
  2. Create. Run the same command without --dry-run. It creates the documentation scaffold, AGENTS.md, agent pointers, and the project skill without replacing existing instruction files.
  3. Ask the agent. Copy the documentation prompt above. The agent should inspect code, configuration, tests, and existing records before replacing starter text.
  4. Check. Run npx @ghostbyte/agent-docs-kit@latest audit documentation --strict. Fix reported missing, stale, or placeholder content.
  5. Continue. Run npx @ghostbyte/agent-docs-kit@latest next after each meaningful update.
Use $manage-project-quality. Inspect this repository and complete the documentation baseline from code, configuration, tests, and existing records. Keep unknowns explicit. Run the strict documentation audit when finished.
SecurityAudit one bounded phase
  1. Initialize first. Complete documentation setup once. A security worksheet cannot be created before it.
  2. Choose a phase. Run npx @ghostbyte/agent-docs-kit@latest list security, then select the narrowest phase matching the risk.
  3. Create the record. For example, run npx @ghostbyte/agent-docs-kit@latest security worksheet api-layer. Every control starts Unverified.
  4. Define boundaries. In the dated worksheet, record the system, target, exclusions, environment, authorization, safety limits, and stop conditions. Do not run active tests without explicit authorization for that exact target.
  5. Collect evidence. Ask the agent to inspect relevant source, configuration, tests, and authorized operational evidence. Complete each control with Pass, Fail, Unverified, or justified N/A.
  6. Validate. Run npx @ghostbyte/agent-docs-kit@latest report validate <worksheet>. Fix missing findings, evidence fields, or an overall status that conflicts with the rows.
  7. Close or hand off. Run next; preserve the dated worksheet as history.
Use $manage-project-quality. Perform a passive security review of [phase] for [scope]. Read the generated worksheet and inspect repository evidence for every applicable control. Keep missing evidence Unverified. Do not run active tests or use credentials without my explicit authorization. Record evidence, findings, remediation, owner, and verification in the dated worksheet.
EngineeringReview one engineering question
  1. Initialize first. Complete documentation setup once so the review has project context and a durable location.
  2. Choose a topic. Run npx @ghostbyte/agent-docs-kit@latest list engineering, then select the topic matching the decision or problem.
  3. Create the record. For example, run npx @ghostbyte/agent-docs-kit@latest engineering worksheet testing-types. Every practice starts Unverified.
  4. Set the question. Record the system or change, goal, constraints, exclusions, and evidence available in the dated worksheet.
  5. Review evidence. Ask the agent to inspect representative code, tests, configuration, measurements, and authorized operational records. Use Applied, Partial, Recommended, Unverified, or justified N/A.
  6. Validate. Separate observed facts from recommendations, record impact, owner, and verification, then run npx @ghostbyte/agent-docs-kit@latest report validate <worksheet>.
  7. Continue. Run next and preserve the dated review.
Use $manage-project-quality. Review [topic] for [system or change] using the generated worksheet. Inspect representative code, tests, configuration, measurements, and authorized operational evidence. Separate observations from recommendations, keep missing evidence Unverified, and record impact, owner, and verification in the dated review.
